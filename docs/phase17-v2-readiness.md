# Phase 17 v2 readiness

Run `python scripts/run_phase17_readiness.py status` to reconstruct league readiness from the sealed cohorts and stored PL source. Run `python scripts/run_phase17_readiness.py verify` to compare that reconstruction with the Phase 17 record and check the starting protected-file snapshot. Both commands are offline and read-only. Neither command captures predictions, retrieves fixtures, schedules collection, settles matches, changes models, or activates a candidate.

BL1 retains `BL1-clean-001`. SA, FL1, and PD have separate empty clean cohorts created through `phase16_cohort.initialize`. Every cohort uses the exact Phase 16 v2 rule and its league's Phase 11 horizon. The historical BL1 Phase 12–15 cohort remains blocked.

The PL adapter reads the archived Phase 7D football-data.org response and source sidecar, applies the exact Phase 7E alias and field-authority contracts, and emits a common fixture event with a stable provider fixture ID. It keeps the date-based Phase 7P canonical ID as a distinct field so kickoff changes do not masquerade as a new provider fixture. The qualification is reconstructable without network access. The archived response contains finished and timed examples; terminal and kickoff-revision behavior is exercised with copies of stored event shapes in focused tests. No actual historical revision or terminal status is claimed from that single archived response.

PL has no Phase 11 league protocol or inherited Phase 11 horizon. The frozen Phase 16 initializer and independent verifier accept only BL1, SA, FL1, and PD. The Phase 7P specification does contain a fixed PL window ending December 31, 2026. Using that window in place of a Phase 11 protocol would establish a new scientific contract. Phase 17 therefore leaves the PL cohort uninitialized and reports `PHASE17_PARTIAL_READY_PL_PROTOCOL_BLOCKED`. A later, explicit PL protocol decision can reuse this adapter qualification without changing the frozen v2 rule or these four cohorts.
